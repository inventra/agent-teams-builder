# 請款小幫手

優先執行隨附程式，不每次重讀原始碼、重寫點擊腳本或逐步傳送截圖。使用者已授權儲存時接續執行；只要預填就不加儲存參數。改寫技能或測試工具本身不表示要新增單據。

## 先收齊輸入

使用者要求影片轉程式、按標籤執行或 `Key收據` 時，先使用相鄰的 [erp-video-automation/SKILL.md](../erp-video-automation/SKILL.md) 與自動化資料庫的欄位契約。每一個自動化都必須有可填的完整表單。

本技能也不得先開 ERP 再問資料。缺必填欄位時一次列出，先補齊；不自行沿用前筆付款日、銀行資料、費用代號或憑證張數。公司等固定值可用本次明確指示或已確認設定，並說明採用值。付款條件與兌現日須明確填值或空字串，不能 null／省略保留未知 ERP 值；收據號碼目前只支援明確空字串。

資料完整性確認不是再要求一次已給過的儲存授權。使用者已指定全部資料或明確沿用時，核對無缺項後直接執行。

## 程式方式

讀 [references/code-control.md](references/code-control.md) 的命令與 JSON 格式，將當次請款資料寫成工作區內的 JSON。代碼與銀行帳號用字串保留前導零，不把歷史示範值當預設。

1. 先完成輸入檢查。資料齊全後，ERP 須已登入並開啟正確公司的 PCMI10；尚未開啟時才進入「作業清單 → 零用金管理系統 → 一般費用請款建立作業」。登入由使用者完成。
2. 已授權建立及儲存的新單，預設只執行一次 `create --request <檔案> --save --review-at-end`。輸入驗證、公司與未存草稿檢查、填寫、明細讀回、儲存一次、取消自動下一張空白單、精確查回及產圖都在程式內完成；正常不用另跑 validate、inspect 或逐欄模型核對。只要求預填時用 `create --request <檔案>`。
3. 每個業務請求固定一個 `request_id`，失敗不得換 ID 重跑。等待現有程序完成，不重啟；一次等待約 30–60 秒，必要時簡短報進度，不在等待中讀整份程式或反覆截圖。
4. 成功回傳 `awaiting_model_review` 表示已儲存、表頭已查回核對，尚待模型檢查明細。只讀短 JSON 及 `images` 指定的兩張圖，比對本次資料：單號、一筆明細、申請人／對象、費用、摘要、金額、收據、專案、付款日、銀行及備註。不可把產圖成功當成核對通過；模糊或截斷處才補局部證據。核對通過後將 journal 記為 `verified` 並記錄模型檢查依據；不符則保留待查狀態並報告差異，不自行重建。
5. `prepared` 是未儲存；`save_attempted`、`save_clicked_verification_pending`、`saved_header_verified` 都先處理原單號，不再儲存或新增。只需要重取最終證據時用 `review --request <檔案> --number <原單號>`，此命令不新增、不儲存，也不覆寫原 journal 的完成狀態。

此設定適用 PCMI10 iGP2.0 16.0.2.1、NTD、員工轉帳、單筆無號碼收據明細。來源文件記載 2026-09-10 完成實單單次新增、儲存、查回及模型最後核對，2026-09-17 加強輸入 gate 並做離線驗證；這是原環境紀錄，不代表新設備或本次共用封裝已獨立複驗 ERP。不要為測試技能額外新增請款。發票、多筆明細、收據號碼、其他版本或自訂欄位應先調整及驗證流程。

## 新視窗與例外

程式每次重新找 HWND，以公司、ERP 程序、視窗類別及 owner 關係判斷。Delphi 對話框可能掛在隱藏 `TApplication` 下；捲軸 `TcxControlPopupScrollBar` 也是獨立視窗，但不是需要確認的對話框。

`dialogs` 可讀跳窗結構。已校準的查詢窗由程式自動操作；其他未辨識的查找或錯誤視窗停下來查看，勿一律按確定。能直接輸入代碼並由 ERP 驗證時，不必額外開查找窗。

程式失敗時先讀錯誤、journal 及當前狀態，保留已填資料。需要視覺判斷才讀 [references/manual-workflow.md](references/manual-workflow.md)，並使用當前可用的 Computer Use 技能接續；不要重新開始新增。視窗不可見再讀 [references/window-recovery.md](references/window-recovery.md)。

需要了解資料格式時讀 [references/demo.md](references/demo.md)。共用版僅保留去識別的格式範例，不能用來還原原影片資料；使用者要求沿用原資料時，須由使用者提供。範例不是新單資料或儲存成功的最新證據。
