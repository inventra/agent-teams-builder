# 從錄影建立可執行流程

1. **先登記影片**。選一個穩定 ASCII 流程 ID 與使用者看得懂的標籤，執行：

   `python video_intake.py extract --source <影片> --library <資料庫> --id <ID> --title <標題> --tag <標籤> --interval 10 --max-frames 60`

   相同影片以 SHA256 找回既有資料夾，不覆蓋紀錄。不同內容使用新資料夾。`--no-frames` 僅做來源登錄，不代表已讀取影片。工具缺依賴時用 --deps 指向可用 PyAV；不要靜默安裝或上傳公司錄影。

2. **粗看全程，再密看關鍵段落**。檢視接觸表找作業入口、第一個新增／查詢按鈕、表單切換、獨立選擇窗、儲存與結果。每一個關鍵點回到全尺寸影格或密集時間段（start/end/interval）；抽不到就继续查看该段，不能用數十秒間隔猜一次滑鼠點了什麼。新增與查詢分清，錯誤重試不照抄成正常流程。

   `video_intake.py` 預設不覆蓋既有資料夾；密集抽取使用資料庫以外的獨立暫存輸出根與不同 ID，檢視後把必要證據及時間戳整理回原流程，勿把暫存段當新可執行業務。音軌如另有說明需讀取或轉錄；沒有處理音軌時明示限制，不假裝已聽到。

3. **盤點所有輸入及結果**。在 workflow.md 列「時間戳→視窗／按鈕→讀寫欄位→所需值來源→完成條件」。區分本次必填、可明確空白、已確認設定、ERP 生成。除了影片填的，也檢查程式所有 edit/grid_set/combo 呼叫、驗證／儲存條件及可能的分支。為各個操作建立 input.schema.json、全 null 範本及離線 input.html；不把影片示範日期或帳號放成預設。

4. **編寫小型執行器**。共用已有窗口／欄位辨識，新的商業步驟放自己的 run.py。輸入 gate 必須在匯入 GUI adapter、尋找 ERP 窗口或啟動作業之前。流程採狀態檢查：公司與版本→目前可編輯狀態→定位控件→输入→原生讀回→保存一次→查回原單→產生證據。定位依即時 HWND、控制項類別、owner 與局部欄名，不能把舊 HWND 或未知畫面絕對座標當跨設備腳本。

   獨立視窗以同 ERP PID、owner 或隱藏 TApplication 關係辨識；未知窗停下來收集資訊，不統一按 Enter。前景被換掉立即停止輸入。等待採明確條件及上限；只重試唯讀或已證明無副作用步驟，儲存不自動重試。保留 request ID、單號、保存階段及錯誤供接續。

5. **先測程式，再測授權範圍**。離線證明缺任何必填／日期反轉／未知欄位時都不載入執行器；重送不新增第二張；查詢分頁不漏資料；產圖不代表核對完成。使用已有紀錄可驗證唯讀查回，新增實單只在使用者這次確實要求時執行。沒有真實驗證的部分維持 needs_calibration，列出需要的影片段落或畫面。

6. **完成交付**。登錄可唯一辨識的 tags，產出可打開的表單及命令，说明已實測範圍和待校準項目；新標籤測試成功後才交付。實際執行採「一個程式跑完整流程，最後模型檢查少量證據」，不每次重建程式。若還有缺少的影片資訊，產出已完成部分並明確指出剩下哪一個步驟，而不是交出空壳宣稱完成。
